01 / purpose

Originals and interpretations stay distinct.

TRACEZERO is a local-first digital forensics investigation and training platform. Its documented initial scope combines case access, secure text-evidence ingestion, custody, deterministic synthetic case generation and a normalized evidence explorer.

Intended users include investigators handling authorized case evidence and learners exploring explicitly fictional training records. This is not a full acquisition suite, arbitrary-file parser or legal-admissibility guarantee.

02 / workflow

Follow the source-defined workflow.

  1. Open an authorized case

    Membership and ownership determine who can view or mutate the case.

  2. Retain text evidence

    Supported UTF-8 .txt, .log, .json and .csv originals are stored privately with custody records.

  3. Generate a fictional case

    The documented CLI creates deterministic synthetic evidence under a pinned scenario/generator version.

  4. Normalize supported sources

    Authorized writers normalize generated JSON; repeated normalization is described as idempotent.

  5. Explore derived records

    Browse filters, original SHA-256, JSON pointers, parser versions and bounded excerpts.

  6. Verify original downloads

    Downloads require current case access and verify SHA-256. Archived cases remain readable and immutable.

05 / security

Controls with explicit evidence levels.

These descriptions retain the source’s evidence level. Documented controls and design intentions are not an independent security audit.

Case authorization / documented
Investigators write assigned/owned cases; assigned viewers read and download. Owners/admins manage membership; admins can access all cases.
Original integrity / documented
Originals stay outside web-served directories, with custody records and SHA-256 verification on download. No legal admissibility is asserted.
Least privilege / documented
Runtime and schema database identities are separate; the application does not use the database root account.
Mutation safety / documented
Archived cases are immutable; conflicting edits are rejected. Synthetic records are fictional and explicitly distinguished from real evidence.

06 / validation

What the sources establish.

The original status document reports phases 01–06 implemented. Source code and project tests were not executed for this portfolio. Unified timeline and later tools are not implemented.

  • Unified timeline and later investigation tools are explicitly not implemented.
  • Uploads allow supported UTF-8 text between 1 byte and 20 MiB; upload acceptance is not parsing support.
  • Normalization accepts only the synthetic JSON contract, bounded to 1 MiB and 100 records per source. Arbitrary real JSON/LOG/CSV parsing is deferred.
  • Excerpts/metadata are bounded at 8 KiB while original downloads remain complete. Fictional virtual/deleted paths imply neither local-path access nor recovered bytes.
  • The status document lists verification commands but no project test counts are inferred. It also records outstanding browser, mobile, keyboard and console checks.

Portfolio tests validate this website, not underlying project outcomes.
